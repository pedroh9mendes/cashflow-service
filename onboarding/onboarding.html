Instalação assistida do ambiente

Bem-vindo à instalação assistida

Este assistente conduz você pelas etapas necessárias para subir o ambiente do CashFlow Service do zero — independente do servidor onde ele será instalado. Cada etapa confirma um pré-requisito ou executa uma ação antes de liberar a próxima, reduzindo o risco de um passo ser pulado por engano.

O que este assistente cobre: pré-requisitos de infraestrutura, escolha do tipo de ambiente, variáveis sensíveis a revisar, o comando de subida, verificação de saúde dos serviços, e os passos pós-instalação (schema do banco e dados de demonstração).

Pré-requisitos de infraestrutura

O ambiente roda inteiramente em containers Docker. Confirme cada item antes de prosseguir — isso vale tanto para a sua máquina local quanto para qualquer servidor onde o ambiente será implantado.

Onde este ambiente será instalado?

A stack é a mesma em qualquer lugar — o que muda é como os serviços são acessados de fora do host. Escolha a opção que descreve este servidor.

Em um servidor remoto, substitua localhost por o IP/hostname do servidor em todas as URLs mencionadas neste assistente e na documentação. As portas continuam as mesmas, mas precisam estar liberadas para a origem que vai acessá-las.

Revise as credenciais padrão

O docker-compose.yml vem com credenciais padrão para subir rapidamente em ambiente de desenvolvimento. Elas nunca devem ser usadas como estão em um ambiente real.

Credencial Valor padrão no repositório Variável para trocar
SQL Server (usuário sa) •••••••••••••••• MSSQL_SA_PASSWORD
RabbitMQ Management ••••• / ••••• RABBITMQ_DEFAULT_USER / RABBITMQ_DEFAULT_PASS
Grafana (admin) ••••• GF_SECURITY_ADMIN_PASSWORD
Chave de assinatura JWT •••••••••••••••••••••••••••••••••••••• Jwt__SigningKey
Login do painel (usuário admin) •••••••• DashboardAuth__Usuario / DashboardAuth__SenhaHash

Os valores acima são exatamente os que estão hoje em docker-compose.yml — não são genéricos. Clique no ícone de olho para revelar cada um. Troque-os editando o próprio arquivo (ou sobrepondo via variáveis de ambiente do host) antes de subir um ambiente que não seja uma estação local isolada.

Importante sobre o login do painel: DashboardAuth__SenhaHash espera o hash SHA-256 da senha, não a senha em texto puro. Calcule o novo hash antes de trocar — em PowerShell: [System.BitConverter]::ToString([System.Security.Cryptography.SHA256]::Create().ComputeHash([System.Text.Encoding]::UTF8.GetBytes("sua-senha-nova"))).Replace("-","").ToLower()
Em qualquer ambiente acessível por mais de uma pessoa ou pela rede, troque todas as credenciais acima antes de subir os containers, e defina Orchestration__AmbienteProducao=true na configuração do statuspage-api — isso bloqueia no backend qualquer tentativa de rodar scripts de schema ou seed de demonstração contra esse ambiente pelo painel.

Subir o ambiente

A partir da raiz do repositório, execute o comando abaixo. Ele constrói as imagens dos três serviços .NET e inicia toda a stack: SQL Server, RabbitMQ, Lançamentos, Consolidado, o painel, Prometheus, Grafana e Alertmanager.

docker compose up -d --build
A primeira execução leva alguns minutos (build das imagens .NET e download das imagens base). Execuções seguintes são mais rápidas, já que o Docker reaproveita as camadas já construídas.

Passos pós-instalação (opcionais)

As tabelas e a política de Row-Level Security são aplicadas automaticamente na primeira subida — nenhum passo manual é necessário para isso. Os dois itens abaixo são opcionais e ficam disponíveis diretamente no painel, na seção "Ações de instalação e carga".

🗄️
Aplicar scripts de banco manualmente

Útil apenas se você quiser reaplicar o schema contra um SQL Server externo ao Docker Compose. O painel pede confirmação do servidor de destino antes de executar, e fica bloqueado enquanto a aplicação estiver em uso.

Popular dados de demonstração

Gera uma carteira de ~20 comerciantes com 30 dias de lançamentos simulados, via chamadas reais às APIs — útil para explorar o dashboard e os relatórios com dados reais em vez de um ambiente vazio.
